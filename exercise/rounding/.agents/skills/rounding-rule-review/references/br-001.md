# BR-001 v1.0

## Rule

Values intended as exact decimal ties are rounded half away from zero. A
displayed value is never a negative zero.

## Scope

Include any function call that can change a numeric value displayed in a report
or used to decide which rows the report includes. Formatting functions can round
as a side effect of display. Finding one `round()` call does not establish
complete coverage.

## Comparison behavior

The reference comparison for this prototype is `cards::round5()` from `cards`
0.9.0. The probe must stop when that exact package version is unavailable.
Normalize a zero comparison result to positive zero before checking display.

This comparison is part of the teaching benchmark. It is not a proposed source
change and is not an endorsement for another intended use.

## Required function catalog

- `round()`
- `signif()`
- `sprintf()`
- `formatC()`
- `format()`
- `prettyNum()`
- `as.character()`

The catalog is the minimum deterministic scan, not a claim of complete coverage.
Wrappers and uncataloged paths require a separately labeled exploratory pass.

## Finding admission rule

A verified finding requires all of the following:

- exact target commit;
- `file:line` and source expression;
- supported explanation of how the call affects display or row selection;
- known display or decision precision;
- an executed probe using decimal ties of both signs;
- a divergence from the comparison behavior; and
- the R, `cards`, skill, and rule versions.

Record weaker evidence as an unresolved candidate. Do not present it as a
verified finding.

## Ownership and unchecked rules

The process owner owns BR-001 and the operating workflow. BR-002 and BR-003 are
outside this skill and must appear as unchecked rules in every report.
